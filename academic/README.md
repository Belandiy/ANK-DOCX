# Academic DOCX

Расширение Quarto для редактируемого академического DOCX и стандартный многофайловый Book-пример. Версия 0.1.0 — техническая основа. Общие стили основной части ЮУрГУ настроены в reference-docx; полный профиль СТО ещё не реализован.

Основания, параметры и ограничения: [общий reference-docx](../docs/REFERENCE_DOCX.md). Базовый текст — TNR 14, одинарный интервал, красная строка 7 мм; нижнее поле 26 мм соответствует СТО 17/19/21, для СТО 04 предусмотрена настройка 20 мм. Актуальный [образец основной части](examples/main-text-math-rules.docx) не содержит титула и сопроводительных листов. [Правила математики](../docs/MATH_RULES.md) различают обозначения в тексте, самостоятельные формулы и пояснения новых символов.

## Установка

Проверено: Quarto 1.10.19, R 4.6.1, Microsoft Word под Windows. Для прямых вызовов Rscript добавьте R в PATH; в корневом build-academic.cmd переносимый R из .tools/R подключается автоматически. Для подготовки среды из каталога academic выполните:

```powershell
Rscript --vanilla tools/install.R
```

Стандартный renv восстанавливает закреплённые в renv.lock зависимости в локальную библиотеку, включая ggpattern и необходимые ему пакеты. Python и reticulate для примера не нужны. На Linux/macOS могут потребоваться системные зависимости R-пакетов; эти платформы не проверены.

Для научных графиков выбран ggplot2. TikZ, PGFPlots и quarto_tikz в рабочий формат не входят; установка TeX-дистрибутива не требуется. LaTeX-разметка формул в QMD сохраняется и преобразуется Pandoc в OMML без компиляции TeX.

Для резервного PNG внутри DOCX с SVG требуется `rsvg-convert` в PATH. Из корня запустите `setup-academic.cmd`: C#-приложение подготавливает librsvg 2.60.0 с проверкой SHA-256 вместе с Quarto и R, а build-academic.cmd подключает инструменты к PATH текущей сборки. Подготовка из исходников требует .NET 10 SDK и официальную Word PIA. В отдельном проекте укажите `ACADEMIC_DOCX_SERVICE` полным путём к опубликованному приложению и подготовьте остальные зависимости.

## Сборка

```powershell
quarto render --to academic-docx --no-clean
```

Результат: `_book/coursework.docx`.

Второй состав из тех же глав и стилей:

```powershell
quarto render --to academic-docx --no-clean --profile referat
```

Результат: `_book/referat.docx`, другой тип работы на титуле и без аннотации.

`--no-clean` сохраняет результаты другого профиля в общей папке `_book`; без этого стандартный Quarto очищает папку перед сборкой.

Перед перезаписью закройте целевой DOCX в Word. Для отдельного результата можно использовать штатный параметр `--output coursework-vector.docx`; пример с улучшенной графикой сохранён именно под таким именем, чтобы сохранить предыдущий открытый документ.

Завершающий R-hook добавляет недостающие нативные поля и источники, затем вызывает C#-команду `finalize-word`. Она использует публичный API Word: Repaginate, обновление полей и TOC, нормализацию и проверку NUMPAGES. Собственная последовательность нужна потому, что готовый doconv::docx_update() ранее сохранял устаревшее число страниц при смене reference. Вызовы PowerShell и непроверенная ветка doconv удалены. Ошибка завершения не считается успешной сборкой; в `.quarto/<имя DOCX>.finalize.json` сохраняется отчёт. Действующий финализатор поддерживается на Windows с настольным Word.

Таблицы по умолчанию занимают область текста между полями: `ank_style_table(ft)` использует готовые `layout = "autofit", width = 1`. Можно передать другую долю `width` или выбрать `layout = "fixed"` для стандартных явных ширин столбцов. Не задавайте `flextable::width()` в расчёте на его действие при autofit: библиотека игнорирует этот параметр в таком режиме.

В Windows модуль C# `WordTables` выполняет недостающую финализацию длинных таблиц: Word вычисляет страницы, Selection.SplitTable разделяет объект, FormattedText копирует шапку с объединениями, а обычные абзацы с REF показывают «Продолжение» и «Окончание». Сначала применяется ширина, затем рассчитываются границы; геометрия столбцов частей фиксируется для их согласованности. Таблица остаётся единой в QMD, а в готовом DOCX состоит из нескольких физических таблиц с общим номером. Колонтитулы и наложенные текстовые блоки для этого не используются. `tables.qmd` показывает 55 нативных формул в таблице с двухуровневой шапкой и итогом, а также обычную Markdown-таблицу.

После вставки шапок документ сохраняется и повторно открывается в Word; обновляются REF/SEQ и номера страниц существующего TOC без его полного перестроения. NUMPAGES пересчитывается до устойчивого состояния; готовый результат дополнительно проверяется по Word PDF. Статистика страниц Word при простом повторном открытии может сохранять иной кэш, поэтому в `academic-docx.cmd check-word` можно передать число печатных страниц флагом `--expected-pages 11`. Актуальные результаты и ограничения — в [правилах таблиц](../docs/TABLE_RULES.md).

`ACADEMIC_SKIP_WORD=1` предназначен только для диагностики промежуточного пакета. Его поля не пересчитаны, пакет содержит известные ошибки схемы; их число зависит от состава работы и фиксируется C#-финализатором без ограничения числа диагностик. После сохранения Word проверенные итоговые документы имеют 0 ошибок. Готовый выпуск без Office эта версия не поддерживает; отсутствие Word нельзя обходить выдачей черновика за итоговый документ.

## Исходники

- `_quarto.yml`: название, автор, стандартный порядок book.chapters.
- `metadata.yml`: сведения об организации, студенте и руководителе.
- `parameters.yml`: коэффициенты и аргументы; a=3 даёт 108, a=5 даёт 166.
- `introduction.qmd`, `model.qmd`: содержание и научная модель.
- `references.bib`: стандартная библиография BibTeX.

Расчёт задан один раз в скрытой R-ячейке model.qmd; данные используют текст, таблица и график. Сложная таблица создаётся публичным API flextable. Это не обещание, что произвольная сложная таблица получается без кода.

Общие стили находятся в `_extensions/academic/academic.docx`. `_extension.yml` подключает их, Pandoc OOXML template и фильтр. В начале вычисляемой главы используется setup.R из расширения: Book исполняет главы отдельно, общее состояние R между ними не предполагается.

## Проверка Word

Фон рисунков прозрачный: расширение использует `knitr.opts_chunk.dev: svglite` и `dev.args.bg: transparent`. Это относится и к SVG, и к резервному PNG внутри DOCX. Параметры драйвера knitr нельзя переносить в `execute`; белые заливки отдельных столбцов и граней поверхности остаются частью оформления графика.

1. Изменить заголовок и обновить настоящее оглавление.
2. Открыть формулу в ячейке в редакторе уравнений и изменить степень: это OMML.
3. Добавить перед таблицей подпись с той же последовательностью «Таблица», обновить поля и проверить ссылки.
4. В «Ссылки → Управление источниками» найти knuth1984 в текущем списке и изменить название на тестовой копии. Обновить поля и проверить изменение списка литературы. Этот UI-сценарий ещё требует ручного подтверждения; автоматическая проверка уже подтвердила источник через API Word и построение BIBLIOGRAPHY. Оформление APA, не ГОСТ.
5. Изменить коэффициент и пересобрать: текст, числовые ячейки, подстановки и график должны измениться согласованно.

Из корня `academic-docx.cmd check-word INPUT.docx COPY.docx REPORT.json` проверяет объекты и изменения на отдельной копии, не редактируя исходный итоговый DOCX. Ожидания читаются из входного пакета; неприменимые сценарии отмечаются как пропущенные. Подробности — в [описании приложения](../tools/AcademicDocx/README.md).

Если Word показывает `{ SEQ ... }`, `{ REF ... }` или `{ TOC ... }` вместо значений, нажмите Alt+F9: это переключение показа кодов полей. Shift+F9 переключает выбранное поле. F9 обновляет значение, но не заменяет переключение режима отображения. Результат PDF-экспорта и текущий экранный режим Word следует различать.

## Границы версии

- Реализован один DOCX-формат. Титул и аннотация демонстрационные; нет задания, рамки и полного нормативного контроля.
- Проверена одна статья с персональным автором. Код также предусматривает Book и InternetSite, но они ещё не испытаны в этом расширении. Групповые цитирования пока завершают сборку явной ошибкой.
- График теперь создаётся ggplot2 и svglite как SVG; в проверенном Word экспорт в PDF сохраняет вектор. Это векторная иллюстрация с резервным PNG, а данные пересчитываются при сборке. Нативная диаграмма Word с редактированием данных пока не реализована. Отдельный экспорт PNG через ragg доступен в 600 dpi; см. tools/graphics-probe.R. Формулы в тексте и ячейках остаются OMML.
- Нумерация объектов сквозная. Приложения ещё не включены в пример.
- Поддержка продолжений относится к нумерованным таблицам с подписью сверху и повторяемой шапкой. Проверены объединения в шапке и OMML в теле; вертикальные объединения в теле длинной таблицы, вложенные таблицы и строки выше страницы отклоняются. Сноски внутри таблицы, сложные группы строк и смешанные ориентации страниц пока отдельно не проверены. Вариант без названия пока не реализован. Табличный кегль 11 пт остаётся демонстрационной настройкой, а не полным профилем СТО.
- Для установки только формата в другой Book нужно добавить project.post-render hook и установить R-зависимости. Одно quarto add не настраивает всю среду.
- В прежней автоматизации QA-экспорт PDF воспроизводил RPC_E_DISCONNECTED при закрытии. C#-команда `export-pdf` отдельно проверяет создание PDF, закрытие и завершение Word и возвращает ошибку при сбое любого шага. Успех конкретных новых прогонов не доказывает исправление всех вариантов RPC-сбоя. Автоматический анализ вёрстки не входит в эту версию.

Инструкция автору: [AGENT_GUIDE.md](AGENT_GUIDE.md). Пересборка заменяет ручные правки прежнего DOCX: Word рассматривается как финальный этап редактирования.
