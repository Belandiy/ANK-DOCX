# Правила взаимодействия AI-агентов (AI Orchestration Rules)

В данном документе зафиксированы правила разделения ролей между агентами в репозитории `ANK-DOCX`.

## 1. Ролевая модель

1. **Главный AI-ассистент (Оркестратор и Архитектор):**
   - Не выполняет непосредственное написание прикладного и системного кода фичей.
   - Отвечает за системную архитектуру, аудит соответствия стандартам (СТО, ГОСТ), декомпозицию эпиков на атомарные задачи.
   - Проводит ревью Pull Request (архитектура, типизация, тесты, отсутствие регрессий) и управляет слиянием в `main`.
   - Поддерживает актуальность проектной документации и памяти проекта.

2. **Агент Jules (`google-labs-jules`):**
   - Автономный разработчик, выполняющий реализацию кода, тестов и исследовательских спайков.
   - Запускается на конкретных задачах трекера GitHub.

## 2. Механизм активации и коммуникации с Jules

- **Активация задач (Issues):** 
  - Новые тикеты активируются автоматически при назначении лейбла `jules`. Дополнительный комментарий-подтверждение после создания тикета писать не требуется.
  - Повторная активация или уточнение требований в существующем тикете выполняется через комментарий с `@jules`.
- **Коммуникация в Pull Requests:**
  - Не писать пустые или подтверждающие комментарии, если Jules уже сообщил, что взял задачу в работу (`Jules is on it`).
  - Комментарии с упоминанием `@jules` в PR пишутся **строго по делу**: замечания по результатам код-ревью, упавшие тесты CI или запросы на доработку.
- **Требования к постановке задачи:**
  - Четкая ссылка на нормативные документы и спецификации в `docs/`.
  - Ограничение скоупа (без оверинжиниринга).
  - Обязательное требование написания или обновления юнит-тестов.
