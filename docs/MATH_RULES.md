# Математические обозначения и расчётные формулы

Рабочее правило для основной части: символы и короткие математические утверждения можно вплетать в текст; самостоятельные расчётные зависимости оформляются отдельными нумеруемыми формулами. Пояснять повторно уже определённые обозначения не требуется. Это правило написания и смысловой проверки, а не новый автоматический нормоконтролёр.

## Основания и интерпретация

Сверено с локальными текстами неизменённого `D:/Repos/AutoNormoKontrol/sources/susu/sto-*/derived/standard.layout.txt`:

| СТО | Пункты |
|---|---|
| 04–2008 | 4.11 |
| 17–2008 | 4.3.8.2–7 |
| 19–2008 | 6.7.2–7 |
| 21–2008 | 8.7.2–7 |

Установлены отдельная строка и свободная строка сверху и снизу; арабский номер в круглых скобках справа; пояснения под формулой в порядке появления символов. Для системы номер располагается напротив середины группы уравнений. Новые обозначения раскрываются с вводным «где» без двоеточия и отступа от левого края, каждое пояснение — с новой строки. Перед пояснениями в формуле ставится запятая, пояснения разделяются точкой с запятой и заканчиваются точкой.

Пункты о пояснениях содержат оговорку о ранее не встречавшихся обозначениях. Для работы принимается содержательная проверка: до формулы уже должны быть объяснены значение и, где применимо, единица каждого обозначения, включая левую часть. Одного появления буквы ранее недостаточно.

СТО не задают формального критерия, отделяющего inline-выражение от самостоятельной формулы. Следующая граница — практика проекта, а не дословное исключение стандарта и не внешнее решение нормоконтролёра.

## Правило для автора

| Запись и её роль | Представление | Пояснения |
|---|---|---|
| Символ `$x$`, индекс `$x_i$` | В тексте, без номера | При первом содержательном использовании |
| Значение исходного параметра `$n=100$` | В тексте, без номера | Объяснить смысл параметра |
| Короткое условие `$x>0$` | В тексте, без номера | По смыслу окружающего текста |
| Самостоятельная зависимость для вычисления | `$$...$$ {#eq-name}`, с номером | Новые обозначения — непосредственно после формулы |
| Формула с уже определёнными обозначениями | Тот же нумеруемый блок | Повторное «где» не нужно |
| Система уравнений | Один display-блок и одна метка | Новые обозначения — после системы |

Длина записи и знак равенства не заменяют смысловую проверку. Даже короткое `$v=s/t$`, вводящее способ расчёта скорости, выносится в отдельный блок. Значение исходного параметра `$n=100$` может оставаться частью предложения. Не добавляй «где» после каждого `$...$`.

Если определены расстояние и время, но ещё не определена скорость, обозначение скорости остаётся новым. При изменении смысла, индекса или единицы обозначение нужно объяснить заново. Пояснение самостоятельной формулы с новыми символами не переносится в конец последующего абзаца.

## Стандартный QMD

Используются [документированные формулы и ссылки Quarto](https://quarto.org/docs/authoring/cross-references.html#equations). Ручные номера и `\tag{}` не нужны.

```markdown
Скорость определяется по формуле @eq-speed.

$$
v=\frac{s}{t},
$$ {#eq-speed}

::: {custom-style="Formula Definitions"}
| где $v$ — скорость, м/с;
| $s$ — пройденное расстояние, м;
| $t$ — время движения, с.
:::
```

`custom-style` — штатное применение стиля Word через Div, `|` — стандартный Markdown line block. Это не отдельный язык описания формул. Содержание пояснений и отсутствие повторов проверяет автор/агент по тексту работы.

Альтернативный пример без повторных пояснений:

```markdown
Пусть $s$ — пройденное расстояние в метрах, $t$ — время движения
в секундах, $v$ — скорость в метрах в секунду. Скорость рассчитывается
по формуле

$$
v=\frac{s}{t}.
$$ {#eq-speed}
```

Это альтернативные примеры: метки в реальной работе должны оставаться уникальными. Пример обоих способов находится в `academic/model.qmd`: после первой формулы объяснены новые обозначения; перед второй определено новое $F(x,a)$, остальные величины уже раскрыты ранее.

## Реализация и границы проверки

- В reference-doc добавлены `Formula` и `Formula Definitions`. Первый имеет нулевую красную строку и интервалы по 17 пт до и после, приблизительно по одной строке TNR 14 при одинарном интервале. Второй начинается от левого края и удерживает строки пояснений вместе. Свободное место при иных размерах многострочной математики проверяется по готовой странице.
- Существующий Word-адаптер применяет `Formula` к нумеруемой display-формуле, сохраняет OMML и `SEQ Формула`. Правый табулятор вычисляется по ширине страницы и полям reference вместо прежней фиксированной позиции. Ссылка содержит обновляемый `REF` и круглые скобки.
- Inline-математика остаётся OMML внутри абзаца, без автоматического номера и пояснений. Алгоритм не определяет смысловую роль произвольной строки LaTeX.
- В старом ANK `definitions="previous"` лишь отключает требование `.equation-where` в `resources/filters/susu-equation-validation.lua`; реальное наличие определений выше по тексту валидатор не доказывает. Классы `.equation`, `.equation-where` и этот атрибут не перенесены в новый конвейер.

Технические подстановки в ячейках расчётной таблицы не перестраивались в формулы основной части; их полное нормативное оформление здесь не заявляется. Для многострочной системы общий номер задаётся одной меткой, но положение номера напротив середины системы в текущем Word-адаптере ещё не проверено. Поддержка `cases`/`aligned` сама по себе этого не доказывает.
