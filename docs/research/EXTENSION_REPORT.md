# Первое расширение Academic DOCX

Обновление графики после первого результата: вместо исходного PNG 96 dpi используются SVG и ggplot2; проверены Word, сохранение вектора в PDF и дополнительный PNG 600 dpi. Текущий renv.lock содержит 82 пакета. Подробности и отдельные итоговые файлы — в [GRAPHICS_QUALITY.md](GRAPHICS_QUALITY.md). Ниже сохранён отчёт о первом срезе, где график ещё был PNG.

29 октября 2026 года создан самостоятельный пример в academic/: стандартный Quarto Book, формат academic-docx, knitr, R и flextable. Из одних глав и общих стилей получены курсовая на 7 страницах и реферат на 6 страницах. Различаются тип работы на титуле и наличие аннотации. Это техническая версия 0.1.0, не подтверждённый профиль СТО конкретного вуза.

Инструкция установки и запуска: [academic/README.md](../../academic/README.md). В подготовленном рабочем каталоге:

```powershell
.\build-academic.cmd
.\build-academic.cmd --profile referat
```

Внутри обычного установленного Book используется `quarto render --to academic-docx --no-clean`. Параметр сохраняет результат другого профиля в общей папке вывода.

## Что предоставляют готовые компоненты

| Задача | Использованное средство |
|---|---|
| Многофайловая работа и порядок глав | Стандартный Book и book.chapters |
| Настройки и ресурсы формата | Quarto Custom Format Extension |
| Исполнение расчёта и значения в тексте | knitr и стандартный inline R |
| Основная математика в DOCX | Pandoc, Office Math |
| Сложная таблица и объединение ячеек | Публичный API flextable |
| LaTeX в ячейке как OMML | flextable::as_equation() и equatags |
| Разбор библиографии | Стандартный BibTeX и pandoc.utils.references() |
| Стили | Общий reference.docx, включённый в расширение |
| Сохранение и обновление полей Word | Готовый doconv::docx_update(), два прохода |
| Установка R-зависимостей | Стандартный renv, а не собственный установщик пакетов |

Прямые зависимости включают flextable 0.10.3, equatags 0.2.2, officer 0.7.7, knitr 1.52, rmarkdown 2.32 и doconv 0.4.2. renv.lock содержит 72 пакета, включая сам renv 1.3.1. Проверены R 4.6.1, Quarto 1.10.19 с Pandoc 3.10 и Word 16.0.20326.20232 под Windows.

officedown не добавлен как ещё один выходной формат: его возможности не переносятся автоматически из R Markdown в Quarto. В этом примере используются компоненты Officeverse непосредственно. Python и reticulate для расчёта и сборки не нужны; Python остаётся инструментом исследовательской проверки и разовой настройки reference.docx.

Официальные интерфейсы: [Book structure](https://quarto.org/docs/books/book-structure.html), [Custom Formats](https://quarto.org/docs/extensions/formats.html), [Project Scripts](https://quarto.org/docs/projects/scripts.html), [as_equation](https://davidgohel.github.io/flextable/reference/as_equation.html). Объекты менеджера источников и поля библиографии описаны в [Microsoft Word Bibliographies](https://learn.microsoft.com/en-us/office/vba/word/concepts/working-with-word/working-with-bibliographies).

## Собственная часть

Расширение создано штатной командой `quarto create extension format:docx`, затем дополнено ограниченным адаптером:

- academic.lua формирует титул и аннотацию из метаданных, сохраняет стандартные источники для завершающего шага, создаёт нативные ссылки и номер формулы.
- finalize.R преобразует подписи Quarto в SEQ с закладками, подключает CITATION/BIBLIOGRAPHY и источники Word, сохраняет ненумерованные заголовки, соединяет рисунок с подписью и вызывает готовое обновление Word.
- document.openxml задаёт порядок служебных листов, TOC и основной части через стандартный DOCX template Pandoc 3.10.
- setup.R задаёт общие настройки flextable. В вычисляемой главе он подключается явно: Book не обязан разделять состояние R между главами.

Это около 250 строк Lua/R с комментариями и пустыми строками плюс 12 строк XML template. Научная модель и пример сложной таблицы находятся отдельно в model.qmd. Проверки Word, SDK, чистой установки и визуального результата не входят в код сборщика. Число строк не является измерением удобства агента или доказательством превосходства над officedown.

Не введены собственные операторы разметки, перечень ресурсов в JSON или самостоятельный механизм склеивания глав. Автор использует стандартные метки Quarto #sec-, #eq-, #tbl-, #fig-, ссылки @... и обычный references.bib. Сложное форматирование таблицы всё ещё требует вызовов flextable; его полное сокрытие от автора этой версией не доказано.

## Проведённые проверки

1. Собраны два состава из одной основной части. Общие стили и текст тела совпадают; повторного шаблона основного содержания для реферата нет.
2. Создана чистая копия исходников без локальной библиотеки, .quarto и _book. Установка через tools/install.R восстановила зависимости из renv.lock, после чего сборка прошла с отключённым R_LIBS_USER. Используется локальная renv-библиотека.
3. В чистой копии изменён только коэффициент a с 3 на 5. Суммы столбцов изменились с 90/18/108 на 148/18/166; итог в двух местах текста тоже стал 166. Изменились подстановки в трёх OMML-ячейках и изображение графика. Основные исходники остались с a=3.
4. В настольном Word на копии реферата обнаружены источник knuth1984, настоящий TOC и три уравнения в ячейках. Через OMath изменена степень с 2 на 3, выполнен BuildUp; после сохранения и повторного открытия правка сохранилась.
5. Перед существующей подписью вставлено дополнительное поле той же последовательности SEQ. Номер таблицы изменился с 1 на 2, обе ссылки REF стали 2. Переименованный заголовок появился в обновлённом TOC. Сохранение, закрытие и повторное открытие DOCX прошли успешно.
6. В итоговых пакетах найдены TOC, три SEQ, шесть REF, CITATION, BIBLIOGRAPHY, источники bibliography/2006, три OMML-формулы в ячейках, горизонтальные и вертикальные объединения. Настоящие Heading 1/2/3 имеют соответствующие outline levels. Word может изменить внутренние styleId при сохранении: проверка учитывает определения стилей, а не только имя ID.
7. Open XML SDK 3.3.0 проверил три финальных DOCX: курсовую, реферат и курсовую с a=5. Во всех трёх 0 ошибок схемы. Приёмочный скрипт проверил 37 утверждений, включая 10 проверок через Word: все прошли.
8. Экспортированы PDF самим Word и просмотрены все 13 страниц двух финальных документов. Обрезанных формул и ячеек нет; рисунок и подпись находятся на одной странице. Большие свободные области отдельных служебных страниц и короткого заключения соответствуют объёму демонстрационного текста; это не результат автоматического анализа заполненности страниц.

Артефакты проверок находятся под build/academic-qa/: verified.json, word-check.json, sdk-validation.json и отдельные журналы PDF-экспорта. Изменённые для эксперимента документы не являются итоговыми файлами для пользователя.

## Существенные ограничения

**Word пока выполняет обязательную нормализацию пакета.** До его обработки SDK находит по 165 ошибок в двух промежуточных файлах, в том числе порядок свойств таблиц/абзацев и повторное pPr. После сохранения Word — 0. Ошибки относятся к промежуточному комбинированному пакету; вклад каждого upstream-компонента и нашего адаптера отдельно не измерен. Нельзя считать их все дефектом flextable или Quarto. Сохранён sdk-before-word.json. Готовая сборка без Word не подтверждена, а ACADEMIC_SKIP_WORD=1 оставлен только как явно обозначенный диагностический режим.

**PDF и DOCX имеют разные результаты закрытия.** Обычный DOCX сохраняется, закрывается и открывается снова без ошибки. При отдельном QA-экспорте PDF создаётся, но следующий Word Close возвращает RPC_E_DISCONNECTED. Это известная незавершённая проблема автоматизации PDF, не скрытая успешными DOCX-тестами. Штатный renderer навыка документов также запускался, но не нашёл LibreOffice; визуальная проверка выполнена по PDF из целевого настольного Word и PNG Poppler. LibreOffice не является частью выбранной сборки.

Проверена только одна библиографическая статья. Поддержка книг и сайтов в коде не равна испытанию этих типов. Групповые цитирования явно отклоняются. Перед расширением библиографии нужно проверить типы и авторов отдельными небольшими случаями.

Общая запись функции в тексте и строка LaTeX для подстановки пока задаются отдельно от R-функции. Согласованное изменение параметра доказано; автоматическое получение математической записи из единого символьного выражения не реализовано. Политика точности чисел тоже не выбрана: десятичная запятая в оформлении не заменяет правила научного округления.

При переносе расширения в другой проект требуются project.post-render hook и объявленные R-зависимости. Одного quarto add пока недостаточно для полной настройки среды. Исходники остаются главным источником: новая сборка заменяет ручные правки DOCX.

## Следующий шаг

Основу Quarto Book + knitr + flextable теперь можно развивать на проверенном примере. Новый общий конвертер не требуется. Следует уточнить реальный нормативный профиль и перенести в общие стили и служебные компоненты только конкретные требования; старые A/B/C остаются контрольными опытами.

Перед обещанием независимости от Word нужен отдельный малый опыт по происхождению ошибок промежуточной схемы и готовым средствам их устранения. Нативные диаграммы, новые типы источников и обратную связь по страницам стоит добавлять по одному проверяемому случаю. Повторное широкое сравнение языков сейчас не даёт практического преимущества.
