# Quarto как третий кандидат академического генератора

После этого опыта требования расширены: важны сложные Word-таблицы, нативные диаграммы, примечания и анализ вёрстки. Актуальная инженерная оценка по этим критериям — в [STACK_DECISION.md](STACK_DECISION.md). Приведённая ниже рекомендация Quarto относится к испытанному сценарию вычислений и двух составов, а не ко всему расширенному продукту.

Quarto проверен практически 28 октября 2026 года. Он даёт готовые вычисления и профили состава работы, но в проверенном DOCX-выводе не создаёт SEQ, REF и встроенные библиографические источники Word. Совместить Quarto с уже написанным нативным слоем удалось. Оснований считать, что Quarto целиком заменяет этот слой или уже уменьшил общий объём программы, нет.

Для следующего прототипа рекомендую Quarto как среду авторских исходников и вычислений, а существующий небольшой слой Lua/OOXML — как реализацию требований Word. Это предварительный выбор архитектуры по расширенному сценарию, не доказательство превосходства Quarto как DOCX writer. Для работ, тесно связанных с R, officedown остаётся разумной альтернативой; прежние A и B сохранены.

## Что было собрано

Использованы те же `demo/content/*.md`, `demo/project.yaml`, `demo/sources.json`, две схемы и общий `reference.docx`. Мост переводит идентификаторы `fig:`/`tbl:`/`eq:` в нотацию Quarto `fig-`/`tbl-`/`eq-`. Математика и содержательные абзацы сохранены. Исходный раздел библиографии выделяется из первого файла, чтобы вычисляемый раздел размещался перед списком литературы.

Добавлен `experiments/quarto/`: общий `work.qmd`, включаемые компоненты титула, задания и аннотации, Python-расчёт и два стандартных профиля Quarto. Курсовая включает задание и аннотацию; реферат исключает их. Оба используют те же главы, вычисления, библиографию, приложения и стили. Это демонстрация композиции, не реализация СТО конкретного вуза.

Итог: `output/c-quarto-coursework.docx` — 11 страниц; `output/c-quarto-referat.docx` — 9 страниц. В каждом три изображения, четыре содержательные таблицы, восемь OMML-выражений, из которых шесть нумеруются, два приложения и три источника Word. График является PNG, а не редактируемой диаграммой Word.

## Готовый вывод Quarto и дополнительные механизмы

Сначала сохранены три stock-документа без собственного фильтра и OOXML-обработки. Затем те же исходники собраны с повторным использованием фильтра B и общего слоя. Нативные возможности итогового файла нельзя приписывать stock Quarto.

| Возможность | Quarto без нашего слоя | Quarto с дополнительным слоем |
|---|---|---|
| Заголовки и стили | Настоящие стили Word; общая нумерация из reference.docx | Сохранены |
| Оглавление | Настоящее поле TOC внутри Content Control | Обновляется Word; перемещено после служебных листов |
| Формулы | Восемь OMML, включая матрицу, cases и aligned | Сохранены; редактирование дроби проверено через API Word |
| Подписи и номера | Числа вычислены при сборке, SEQ отсутствует | Настоящие SEQ; ограничение совместимости с русским диалогом «Вставить название» сохраняется |
| Числовые перекрёстные ссылки | Гиперссылки с рассчитанным текстом; REF отсутствует | Настоящие REF и закладки |
| Источники и библиография | Citeproc, текст и гиперссылки; источников Word нет | Три встроенных источника, CITATION и BIBLIOGRAPHY |
| Аннотация и статистика | Метаданные подставлены при сборке; маркер статистики ещё не обработан | NUMPAGES и DOCPROPERTY; счётчики объектов вычислены при сборке |
| Приложения | Для исходной нотации app: понадобилась адаптация в явные ссылки | Отдельные SEQ и REF; буквы А/Б назначаются при сборке |
| Два состава документа | Готовые profiles, conditional content и includes | Сохранены |
| Вычисляемые значения | Выполняются Jupyter/Python либо knitr/R при сборке | Сохранены; поля Word не запускают эти расчёты |

`native-adapter.lua` адаптирует нотацию и передаёт объекты неизменённому `scripts/native-b.lua`. После создания полей метки подписей удаляются из обработки Quarto, чтобы он не добавлял второй статический номер. Одного подключения фильтра B оказалось недостаточно: в первой пробе появились двойные подписи и повторяющиеся закладки. В итоговых пакетах повторяющихся имён нет.

Нативный TOC Quarto первоначально размещался перед нашим титульным листом. Его перемещение, исключение служебных заголовков из нумерации и оглавления, а также PAGE выполняются программно. Поэтому общий reference.docx не решает всю компоновку.

## Проверка вычислений

`parameters.yml` задаёт длину 20 и ширину 12. Python один раз вычисляет площадь и набор точек, используемые в прозе, таблице, графике и повторной итоговой фразе. Quarto выполняет ячейки и inline-выражения. При переопределении только длины на 35 результат меняется с 240 на 420.

Автоматически проверены изменение значения в тексте и нативной таблице, изменение встроенного изображения графика при неизменности двух исходных схем, а также JSON с рассчитанными точками. На графике результат дополнительно подписан числом. Cache и freeze отключены. Для параметров Jupyter понадобился Papermill; одного наличия Python и Quarto оказалось недостаточно.

Отдельный минимальный документ `r-probe.qmd` выполнен через knitr: выражение `r area` вставило 240. Это подтверждает два отдельных движка. Свободное смешивание R и Python в одном документе не проверялось. Расчёты и смена профилей для A/B заново не реализовывались, поэтому утверждать, что Quarto требует меньше кода, чем officedown для этого расширенного сценария, пока нельзя.

Числа и графики обновляются при пересборке исходников. Ручная правка числа в Word не запускает Python/R. Содержательные выводы меняются автоматически только тогда, когда автор явно описал соответствующее вычисление или условие.

## Проверка в Microsoft Word

Все действия выполнялись через объектную модель настольного Word, без мыши и клавиатуры. Итоговые DOCX сохранены и повторно открыты обычным методом, без OpenAndRepair. Для курсовой повторён существующий стресс-сценарий: вставка изображения и SEQ, изменение заголовка, правка числителя OMML, добавление текста, изменение источника в закрытом пакете и обновление в Word после открытия.

Результат `scripts/verify-quarto.py`: **5/5** проверок композиции, **5/5** вычислений и **14/14** поведения Word. Текст основной части и имена стилей её абзацев совпадают у двух профилей. Ссылки на первые два рисунка меняются 1→2 и 2→3; изображений становится четыре. Редактирование числителя сохраняется как OMML. Цитирование и библиография отражают изменённый источник. Объём меняется с 11 до 16 страниц, NUMPAGES показывает 16. Ошибок обновления и отображаемых ошибок полей не обнаружено.

Ограничения прежнего корпуса сохраняются: DOCPROPERTY Figures после вставки четвёртого изображения остаётся равным трём; перестановка и удаление целей ссылок, автоматическая перестановка букв приложений и изменение источника через диалог менеджера Word ещё требуют отдельной проверки. Библиография испытана на трёх веб-источниках и стиле APA, не на всём академическом наборе типов и стандартов.

### Структурная проверка

| Пакет | Замечания Open XML SDK 3.3.0 |
|---|---:|
| Stock Quarto с нашей общей reference.docx | 53 |
| Quarto с адаптером нативных полей до общего завершения | 5 |
| Итоговая курсовая после Word | 0 |
| Итоговый реферат после Word | 0 |

В stock замечания относятся к порядку элементов jc, pPr, spacing, shd и четырём известным замечаниям Pandoc к OMML m:count. Количество относится к этому корпусу и этим версиям; это не универсальный рейтинг библиотек. Нулевая схема после Word не заменяет практическую проверку. Office-free выпуск готового документа здесь не доказан.

### Отдельный сбой экспорта PDF

При дополнительном экспорте для визуальной проверки PDF создавался, но следующий Document.Close воспроизводимо возвращал RPC_E_DISCONNECTED. Это наблюдалось у stock Quarto и у итогового C. Контрольный экспорт существующего B завершался без этой ошибки. Первопричина не локализована, приписывать её однозначно Quarto нельзя: корпуса различаются, в C есть дополнительный график.

При обычной сборке DOCX без экспорта PDF сохранение, закрытие, повторное открытие и стресс-тест проходят. Поэтому DOCX-проверка отделена от необязательного экспорта для QA; последний сохраняет `closed: false` и текст ошибки в отдельном JSON, а не считается чистым закрытием. PDF не является продуктовым результатом стенда. Все 20 страниц двух финальных документов проверены визуально по PDF, созданным Word, и PNG. Версия Word 16.0.20326.20232. Штатный renderer остаётся недоступен без LibreOffice, как в исходном сравнении A/B.

## Объём собственной логики

Непустые физические строки без строк, начинающихся с комментария:

| Часть | Строки | Назначение |
|---|---:|---|
| `quarto-experiment.py` | 151 | Подготовка общего корпуса, адаптация, компоновка, запуск и сбор свидетельств |
| `native-adapter.lua` | 46 | Совместимость нотации и обработки Quarto с фильтром B |
| `native-b.lua` | 49 | Уже существующая реализация SEQ/REF, повторно использована |
| `quarto-export.ps1` | 26 | Только визуальная QA и регистрация проблемы Close |
| `verify-quarto.py` | 79 | Только проверки эксперимента |

Общий OOXML-модуль, шаблон, Word-финализация и инспектор повторно использованы. Приведённая 151 строка включает оболочку исследования, а прежние 46 для A и 49 для B считали только адаптеры; напрямую сопоставлять эти суммы некорректно. QMD научного расчёта относится к содержанию работы, а не универсальному движку оформления.

Итого на этом этапе собственный код не сократился. Quarto заменил необходимость разрабатывать исполнение ячеек, inline-выражения, параметры, profiles, includes и conditional content. Сколько кода это экономит относительно альтернативы с тем же набором возможностей, требует одинакового расширения A/B. Сохранять две разные нотации ID в будущем не обязательно: часть адаптера обусловлена совместимостью со старым корпусом.

Quarto 1.10.19 включает Pandoc 3.10, совпадающий по версии с A/B. Windows ZIP проверен по SHA-256 из метаданных официального релиза. Python-окружение вычислений содержит 63 пакета с транзитивными зависимостями; многие уже были установлены. Снимок для Windows сохранён в `experiments/quarto/requirements.lock.txt`. Для R-пробы используется существующая установка R. Полная установка и проверки на Linux не проводились.

## Рекомендация и оставшиеся вопросы

Разумный следующий вариант — общие Markdown/QMD и метаданные, Quarto для исполнения и состава, один набор Word-стилей, единый фильтр полей и библиографии и отдельная финализация Word. Полноценный собственный writer, система плагинов и сложное наследование профилей не нужны. Минимальные профили уже работают без format extension.

Перед выбором для продукта остаются реальные титульные листы и секции по требованиям вуза, устранение или обход сбоя PDF-экспорта, расширение типов источников и проверки пользовательских правок. Quarto format extensions, Quarto books, смешивание R/Python в одном документе и комбинация Quarto с officedown не исследованы. Сравнение поддерживает Quarto как полезный авторский слой, но не как готовую замену нативной документной механики.
