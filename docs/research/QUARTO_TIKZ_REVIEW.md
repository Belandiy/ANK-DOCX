# Оценка quarto_tikz для академического DOCX

Статус направления: закрыто по решению пользователя. В рабочем проекте выбран ggplot2 с экспортом SVG; TikZ, PGFPlots и quarto_tikz исключены. Ниже сохранены результаты опыта и первоначальная рекомендация на момент исследования; она больше не является планом интеграции.

29 октября 2026 года. Рассмотрены README, лицензия, Lua-фильтр и открытые issues [danmackinlay/quarto_tikz](https://github.com/danmackinlay/quarto_tikz). Проведён отдельный опыт под Windows. Основной проект academic/ не изменялся.

Рекомендация: использовать как основу необязательной интеграции TikZ/PGFPlots после исправления Windows и добавления строгого контроля результата. Делать его обязательным способом построения всех графиков оснований нет. Собственный универсальный конвертер TikZ → SVG писать не требуется.

## Что это даёт

Автор помещает обычный TikZ-код в блок `.tikz` внутри QMD. Фильтр компилирует его через TeX, преобразует в SVG для DOCX и передаёт изображение Quarto. Для PGFPlots достаточно подключить соответствующий TeX-пакет, как в примере. Это отдельный рендерер иллюстраций, не замена knitr, R, Pandoc или нашего слоя нативных полей Word.

Фильтр допускает LuaLaTeX/XeLaTeX и общий TeX-template. Так можно один раз задать шрифты, кириллицу, пакеты и стили графиков. Для подписей и ссылок README рекомендует стандартный fenced div Quarto `::: {#fig-name}` с подписью последней строкой; внутренний `%%| caption:` одновременно с ним применять не следует. HTML-вариант TikZJax для DOCX не подходит.

Требуются TeX-дистрибутив и преобразователь PDF → SVG. В опыте использованы уже доступные LuaLaTeX и pdftocairo из TeX Live 2026. Inkscape не понадобился: pdftocairo является предусмотренным публичным вариантом svg-engine. Для совместимого PNG внутри DOCX использован ранее проверенный librsvg 2.60.0.

## Результаты опыта

| Проверка | Результат |
|---|---|
| Исходная версия под нашим Windows/Pandoc | Ошибочно сообщает, что lualatex не найден, хотя executable есть в PATH |
| Причина | Pandoc возвращает `pandoc.system.os = mingw32`, фильтр сравнивает с windows; не добавляются .exe и неверно выбирается разделитель TEXINPUTS |
| После минимального патча | Схема из пользовательского TeX-примера и PGFPlots-график затухающей синусоиды с кириллицей собираются в DOCX |
| Структура | В DOCX два SVG; необработанного TikZ-кода нет |
| Настольный Word | Открытие, сохранение и PDF-экспорт успешны; просмотрена вся страница |
| Вектор при PDF-экспорте | Растровых Image XObjects нет: оба рисунка остались векторными |
| Схема OOXML | У исходного вывода Quarto было 5 ошибок свойств; после обычного сохранения Word — 0. Источник этих ошибок отдельно не локализован |
| Ошибочный TikZ | Команда завершается с кодом 0, а исходный некомпилируемый код остаётся в DOCX |
| Флаг --fail-if-warnings | Не остановил этот случай: ошибка фильтра зарегистрирована через его журнал |
| Кэш и внешний параметр | При cache:true изменение parameters.tex с A=1 на A=2 оставило прежний SVG; после сборки без кэша SVG изменился |

Отрицательные случаи проверены исполнением, а не только чтением README. Доказательства находятся в build/tikz-probe/evidence.json, word-evidence.json, sdk.json и журналах сборки. Приёмочный график использует параметр A=1; файл параметров после опыта восстановлен.

Прямой установщик Quarto с полным commit-суффиксом и URL tar.gz в этой среде не завершился успешно. Зафиксированный ZIP скачался корректно; установка из распакованного локального каталога через штатный quarto add прошла. Обычная установка текущей main по команде README отдельно не проверялась. Это не основание менять архитектуру или писать собственный установщик расширений.

## Условия включения в продукт

1. Зафиксировать версию и Windows-патч либо взять upstream-версию с подтверждённым исправлением. Остальные ОС с нашим патчем не проверялись.
2. Оставить cache:false для графиков с внешними данными и общими TeX-файлами, пока нет отслеживания этих зависимостей. Если параметры меняют сам текст блока, это другой случай: он входит в ключ кэша. Обнаруженный дефект относится именно к изменениям внешних файлов.
3. Проверять, что каждый предназначенный для рендеринга блок дал изображение; ошибка диаграммы должна завершать нашу сборку ошибкой. Строгий режим интеграции ещё не реализован. Одного статуса Quarto или fail-if-warnings недостаточно в проверенном случае.
4. Проверить совместно с academic-docx стандартный fig-ID, нативные SEQ/REF и повторную сборку при изменении расчёта. В нынешнем опыте использованы штатные подписи и ссылки Quarto; их наличие не доказывает нативные поля Word. Эта интеграция пока не выполнена.
5. Хранить общие настройки TeX и оформления в профиле. Автору нужен код конкретной схемы или графика, а не ручная настройка конвертации и Word.

Опыт был одностраничным QMD в одном каталоге. Работу в нашем многофайловом Book нельзя считать проверенной по этому результату. В upstream также открыт [issue #24 о поиске шаблона для QMD в подкаталоге](https://github.com/danmackinlay/quarto_tikz/issues/24); его причина в этом опыте не исследовалась.

SVG остаётся иллюстрацией. Математические обозначения внутри неё не становятся OMML, а данные — редактируемой таблицей диаграммы Word. Для самостоятельных формул основного текста следует сохранить существующий Pandoc → OMML. Для статистических графиков R/ggplot2 также сохраняет смысл: TikZ не обязателен для каждого набора данных.

Исходники опыта и порядок повторения: [experiments/tikz/README.md](../../archive/legacy/experiments/tikz/README.md). В основном формате academic-docx новый фильтр не подключён; результаты не означают принятого решения о его обязательном использовании.
