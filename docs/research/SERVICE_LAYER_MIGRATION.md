# Приёмка переноса служебных Python/PS1-инструментов на C#

Дата: 29 октября 2026 года. Статус: переход подключён и проверен. Машинный итог — [summary.json](evidence/csharp-migration/summary.json).

## Что изменено

Созданы `tools/AcademicDocx.Core` и `tools/AcademicDocx`. Библиотека на Open XML SDK 3.3.0 проверяет схему, читает технические свойства и настраивает reference-docx. Windows-приложение управляет Word, делит таблицы, обновляет поля и страницы, проверяет объекты на отдельной копии, экспортирует PDF и подготавливает окружение.

Quarto Book, вычислительный путь knitr/R, flextable, equatags, графические библиотеки и штатные Lua-фильтры сохранены. В `finalize.R` заменён вызов PowerShell на опубликованную C#-команду. Прямые преобразования OOXML в этом R-hook пока сохранены; их перенос в SDK является отдельным следующим участком.

Удалены восемь PS1, Python-редактор стилей, requirements.txt и отдельный старый SDK-валидатор: всего 13 файлов. В поддерживаемых исходниках нет собственных `.py`/`.ps1`; история, `build/`, локальные инструменты и внутренние файлы сторонних R-зависимостей не очищались по расширению.

| Прежний инструмент | Замена |
|---|---|
| setup.ps1, bootstrap-r/quarto/graphics.ps1 | `setup-academic.cmd` и C#-команда `setup` |
| update-word.ps1, tables-word.ps1 | `WordFinalizer.cs`, `WordTables.cs`, `WordSession.cs` |
| check-word.ps1 | `check-word`, ожидания из входного DOCX и явно пропущенные неприменимые сценарии |
| quarto-export.ps1 | `export-pdf`, раздельный результат создания PDF/закрытия/завершения Word |
| style-reference.py | `style-reference` на Open XML SDK |
| tools/validate | `validate` в том же приложении; ошибка схемы даёт ненулевой exit code |

Непроверенная не-Windows ветка doconv удалена. Прямая зависимость doconv и семь более не используемых транзитивных пакетов удалены из renv.lock штатным `renv::snapshot()`. `renv::status()` подтвердил согласованное состояние. Установленные сторонние пакеты на машине не удалялись.

## Сборка из QMD и PDF

После удаления старых инструментов выполнены обычные команды:

```powershell
.\build-academic.cmd --output coursework-csharp-qa.docx
.\build-academic.cmd --profile referat --output referat-csharp-qa.docx
```

Обе завершились с exit code 0. Для сохранения открытых пользовательских результатов использованы новые имена файлов.

| Профиль | Страниц Word / PDF | Ошибок SDK | Жизненный цикл Word |

| Реферат | 10 / 10 | 0 | Документ закрыт, свой процесс завершён |

Результаты — `academic/_book/coursework-csharp-qa.docx`, `academic/_book/referat-csharp-qa.docx`. Отчёты финализатора: [курсовая](evidence/csharp-migration/coursework-finalize.json), [реферат](evidence/csharp-migration/referat-finalize.json).

PDF получены новой командой `export-pdf`; число страниц независимо прочитано Poppler pdfinfo. В обоих случаях создание PDF, закрытие документа и завершение своего Word прошли успешно: [курсовая](evidence/csharp-migration/coursework-pdf.json), [реферат](evidence/csharp-migration/referat-pdf.json). Страницы 8–10 курсовой растеризованы Poppler и просмотрены: заголовки частей, объединённая шапка, строки с формулами и итог не обрезаны. Это визуальный QA конкретных страниц таблицы, не полный автоматический нормоконтроль.

## Выявленное расхождение и его устранение

Первый полный перенос мог разделять контрольную таблицу после первой строки данных и выдавать 12 страниц, хотя старый PS1 на том же входе давал 11. Были сопоставлены реальные строки, границы страниц и PDF. Дополнительные PrintPreview и сохранение до разделения не устранили расхождение и удалены из реализации.

В приватном окне C#-автоматизации теперь явно задаётся `View.ShowFieldCodes = false`: измеряется документ с результатами полей, независимо от сохранённого режима их показа. После этого полный документ стабильно прошёл приёмку и дал 11 страниц. Общий порядок нормализации, обновления полей и проверки NUMPAGES сохранён. Вводить задержки по времени не потребовалось.

В новой вёрстке в первой части таблицы помещается 18 строк данных вместо 17 у контрольного PS1-прогона. Во всех частях сохранены данные и шапки, каждый фрагмент остаётся на своей странице, общее число страниц совпадает. Побайтовая идентичность DOCX и прежнее распределение каждой строки по страницам не заявляются. Режим отображения задаётся только в окне собственного Word; существующие пользовательские документы не открываются автоматизатором.

## Подготовка и поставка

Опубликован self-contained win-x64-каталог `.tools/academic-docx/`; отдельная interop DLL не включена, используются встроенные типы официальной установленной Word PIA. Версии: .NET SDK 10.0.401, runtime 10.0.12, Word 16.0.20326, PIA 15.0.4603.1000, Quarto 1.10.19, R 4.6.1, librsvg 2.60.0.

`setup-academic.cmd` и C#-команда `setup` проверены на существующем окружении: версии совпали, библиотека renv согласована с lock-файлом. Доверие Authenticode проверяется готовым WinVerifyTrust, не извлечением одного сертификата. Отдельная проверка того же скомпилированного метода приняла подписанный Microsoft dotnet.exe и отклонила неподписанный вход: [authenticode.json](evidence/csharp-migration/authenticode.json). ZIP по-прежнему проверяются SHA-256 до распаковки.

Свежая установка на совершенно чистой машине и другие версии/ОС не испытаны. Для сборки приложения из исходников нужны .NET 10 SDK и официальная PIA; для конечной финализации нужен настольный Word. Успешные PDF-прогоны не являются доказательством устранения любых исторических RPC-сбоев Office.
