# Ограниченная проба C# / Word COM / Open XML SDK

Дата: 29 октября 2026 года. Это исследовательский код, не вторая рабочая сборка и не готовый финализатор.

Результат и архитектурное решение: [SERVICE_LAYER_ARCHITECTURE.md](../../../SERVICE_LAYER_ARCHITECTURE.md).

## Задача

На копии существующего промежуточного документа проверить доступность из современного C# операций, ради которых сейчас используется PowerShell: фактические страницы Word, разделение таблицы через Selection, копирование объединённой шапки, нативное поле REF, сохранение, повторное открытие и стабилизация NUMPAGES. Дополнительно проверить структуру через уже используемый SDK и завершение собственного Word.

Проба выполняет только первое разделение длинной таблицы. Она ожидает конкретную форму исследовательского документа: три таблицы, вторая с двухстрочной шапкой, закладка tbl_squares. В полноценный продукт эти ограничения как универсальный контракт не переносятся.

## Файлы

- `Program.cs`, `Probe.csproj`, `packages.lock.json` — итоговый исходник и зависимости.
- `input.docx` — неизменённая копия промежуточного файла, полученного действующим конвейером до Word; содержит известные ошибки схемы. Это тестовый вход, не готовый документ.
- `report.json` — успешный итог: 11 проверок, 0 ошибок схемы SDK, exit code 0.
- `report-attempt-1.json` — первая попытка с ошибкой NUMPAGES: до восстановления порядка сохранения/повторного открытия и стабилизации. Первый вариант исходника отдельно не сохранён; отчёт фиксирует наблюдение, воспроизводимая команда ниже относится к итоговому исходнику.
- `environment.json` — версии и SHA-256 исходника и входа.

## Повторение в PowerShell

Нужны Windows, установленный настольный Word, .NET 10 SDK и официальная Word PIA из Office/средств разработки. Пример пути ниже относится только к проверенной машине. Не скачивать вместо неё неподдерживаемую NuGet-перепаковку с похожим названием.

Из корня репозитория:

```powershell
$taskPia = 'C:/Windows/assembly/GAC_MSIL/Microsoft.Office.Interop.Word/15.0.0.0__71e9bce111e9429c/Microsoft.Office.Interop.Word.dll'
dotnet build docs/research/probes/csharp-word/Probe.csproj -p:WordPiaPath=$taskPia -p:RestoreLockedMode=true
New-Item -ItemType Directory -Path build/service-layer-csharp-probe -Force | Out-Null
dotnet docs/research/probes/csharp-word/bin/Debug/net10.0-windows/Probe.dll docs/research/probes/csharp-word/input.docx build/service-layer-csharp-probe/result.docx build/service-layer-csharp-probe/report.json
```

Программа копирует вход в отдельный выход, создаёт свой экземпляр Word и не подключается к активному документу пользователя. Выход и отчёт перезаписываются. Существовавшие до опыта процессы Word не завершаются. Исходный вход не изменяется.

В PIA используются встроенные interop-типы. Проверка списка ссылок итоговой сборки подтверждает отсутствие зависимости от отдельной Microsoft.Office.Interop.Word.dll при запуске этого опыта. Наличие установленного Word остаётся обязательным.

## Ограничения доказательства

Не проверены полный перенос алгоритма разделения, негативные случаи, совпадение всех страниц с рабочим выпуском, PDF, установка на чистую машину, self-contained-поставка и Linux-сборка. Не измерены скорость разработки, число исправлений агента или сравнительная стоимость Python/C#.

Успешная проба снимает конкретный риск interop-совместимости. Она не является разрешением переключить рабочую сборку без проверки всего заменяемого участка.
